# Research and measurement protocol
Research question: does an availability-aware combination of TF-IDF content, implicit collaborative similarity and popularity improve held-out discovery relative to single components?
Use scripts/evaluate.py with real timestamped events. A global chronological cutoff prevents future signals leaking into training. Exclude previously seen items from relevance because serving excludes them. Report eligible users, catalog coverage/data provenance and per-component comparisons. Current script emits macro Precision@K, Recall@K and NDCG@K; small data and popularity bias limit conclusions. Two-user support is a heuristic, not an optimized scientific finding.
Use scripts/benchmark.ps1 against an isolated running deployment. Record CPU/RAM, image versions, users, spawn rate, duration, request errors and actual Locust CSV/HTML. Tests write genuine interaction events. No benchmark has run in this environment, so no numerical performance report is available. Generated outputs should be attached to the final verification record when executed.
The original documents name papers without supplying their full contents or bibliographic verification. This package does not assert paper reproduction, novelty, publication acceptance or improvements over published results.
