# Phase 2 implementation plan
User-approved changes supersede SQLite-owner design in the audit. PostgreSQL is the shared source of truth; Redis is disposable caching; Redpanda remains the broker. No Phase 3 work starts in this checkpoint.
1. Add SQLAlchemy/psycopg repository and Alembic migration: events with unique UUID and canonical payload, outbox with unique event reference, consumer processed-event ledger keyed by consumer/version/event, signal-version metadata. Add user history and pending-outbox indexes. Preserve old SQLite database; provide explicit export/import dry run and backup, never deduplicate uncertain legacy rows heuristically.
2. Intake commits canonical event and outbox together. PostgreSQL ON CONFLICT and payload comparison handle concurrent identical retries versus 409 conflicts. Rollback returns failure and creates neither row. Preserve legacy routes and catalog.
3. Relay claims work with SKIP LOCKED and expiring leases; publishes stable IDs keyed by user; checks delivery future; marks acknowledgment only after success. Crash after send may resend safely. Backoff is bounded; pending data is never silently discarded.
4. Consumer uses manual offset commits after a transaction containing both processed marker and projection update. Replay is a no-op. Commit offsets in partition order; transient failures block advancement; invalid records require durable quarantine before advancing.
5. Cache recommendations in Redis using model version, user, limit and committed signal version. TTL bounds occupancy. Never cache event writes. Redis outage falls back to PostgreSQL computation; cache failures do not reject accepted events. Versioned keys prevent stale writers overwriting fresh entries; old keys expire.
6. Add actual PostgreSQL transaction/concurrency/migration tests and Redis hit/miss/outage/version tests. Test live broker delayed startup, duplicate delivery, relay crash windows and consumer restart before offset commit when runtimes are available. Label unavailable integration checks explicitly; mocks do not certify asynchronous broker operation.
7. Introduce only the minimal Compose services/configuration needed to test PostgreSQL, Redis and Redpanda during Phase 2; retain named persistent volumes. Full service separation, advanced orchestration and optional monitoring remain later phases.
Planned files: backend/app/storage.py, schemas.py, outbox.py, worker.py, cache.py; backend/alembic.ini and migrations/; backend/requirements.txt; backend/app/main.py; docker-compose.yml; .env.example; backend/tests/test_postgres.py, test_cache.py, test_outbox.py; docs/MIGRATION.md and PHASE2_VALIDATION.md.
Exit gate: demonstrated atomic intake, conflict-safe retries, replay-safe consumer effects, cache invalidation/fallback, and measured asynchronous processing in the available integration environment. No performance or quality numbers will be invented.
